# Extend verb

**ID:** `pixhaus.builtin.extend`  
**Stream:** S25

Generates directional sprite views from a single source frame. Given a front-facing sprite, Extend synthesises the remaining compass directions (west, north, east for a 4-direction set; all eight cardinal and diagonal for 8-direction).

Each generated direction lands in its own layer, named `"{layer_name} – {Direction}"` (for example, `"Extend – West"`), with a single cel at the active frame.

## When to use

Use Extend when you have one facing direction drawn and need the others — the typical RPG character workflow where the artist draws the south-facing frame first and wants the rest generated to match the same palette and pixel style.

## Inputs

| Field | Type | Default | Description |
|---|---|---|---|
| `source` | pixel buffer | required | The frame to extend from. Must be RGBA8. |
| `source_direction` | direction | `south` | Which direction the source sprite is currently facing. |
| `direction_set` | set | `four_direction` | Which directions to generate. See below. |
| `style_intensity` | 0.0–1.0 | `0.8` | How closely the output should match the source's palette and pixel style. Higher values = stricter fidelity; lower values = more creative latitude. |
| `layer_name` | string or null | `"Extend"` | Base name for generated layers. |

### Direction sets

- `four_direction` — South, West, North, East. The source direction is excluded from the output.
- `eight_direction` — All eight compass directions (S, SW, W, NW, N, NE, E, SE). The source direction is excluded.
- `custom` — Explicit list of directions. Duplicates are silently removed. The source direction, if present, is skipped.

### Direction values

`south`, `south_west`, `west`, `north_west`, `north`, `north_east`, `east`, `south_east`

## Output

One `AddLayer` effect per generated direction. Each layer:

- Name: `"{layer_name} – {Direction}"` (en-dash U+2013).
- Single cel at the active frame, same canvas dimensions as the source.
- RGBA8 pixels generated by the selected backend.

The verb's thumbnail shows the first generated direction's pixels.

## Errors

| Condition | Error |
|---|---|
| No active sprite in context | `MissingContext("active sprite")` |
| No backend or backend lacks view synthesis | `Backend(...)` |
| `style_intensity` outside `[0.0, 1.0]` | `Schema(...)` |
| Custom direction set is empty | `Schema(...)` |
| All direction synthesis calls fail | `Backend(...)` |
| Cancelled | `Cancelled` |

Individual direction failures are non-fatal: the verb logs a warning and continues to the next direction. Only if every direction fails does the verb return an error.

## Backend requirements

`IMAGE_GENERATION | VIEW_SYNTHESIS`. The backend must implement the `ViewSynthesisBackend` sub-trait (exposed via `InferenceBackend::as_view_synthesis`). Suitable backends: Replicate (TripoSR-class geometry estimation), Stability (style-conditioned image generation).

## Cancellation

The verb checks the cancellation token between direction synthesis calls. Cancelling mid-run discards any directions not yet submitted to the backend. Directions already in flight continue to completion (the backend call itself is not aborted — use the backend's own timeout for that).
