## mod-codex

This group is high-quality, convention-faithful UI code, and the strongest part of the codebase audited here. Across both units the load-bearing rules hold: the deferred-intent panel model (`&self` panels reading the read-only `CodexView`/session mirror and pushing `Intent` for every mutation), clean error/panic hygiene, exemplary tracing (one structured `info!` on register, zero per-frame events), and design-system discipline (theme tokens, phosphor icons, shared widgets, no hex or emoji). The one real defect is a medium-severity i18n leak in `details.rs` where `enum_picker` renders enum variants through `format!("{v:?}")` instead of the localization service; the remaining findings are low/info maintainability and polish items. Fix the i18n leak and this group is exemplary.

### Strengths

- i18n discipline is exemplary across both units: every label, title, and hint resolves through `tr("codex.*")` at render time, with keys verified present in `codex.yaml`, while project content (entry names, descriptions, palette RGBA, slot labels, version author) is correctly treated as DATA shown verbatim, never keyed.
- Deferred-intent model is followed precisely: every panel is a `&self` unit struct reading the read-only mirror and pushing an `Intent` for each mutation (50 intent pushes across the second unit), with no direct model writes, no `RefCell`/`Cell`/`Mutex` smuggling, and egui temp memory / the shell-owned `CodexEditorDraft` and `scope.scratch` used only for transient UI affordances.
- `keys.rs` cleanly owns the module's `codex.*` namespace via stable enum-to-key mappers (status/relation/entry_type/priority/anchor_kind/anchor_strength/color_role/coverage_status), each returning a `&'static str` the shell localizes — the "core stores the enum, shell localizes" rule — backed by uniqueness and prefix tests in `mod.rs` that assert structure rather than mirroring literals.
- Tracing is exemplary: a single structured `tracing::info!(module = "codex", ...)` on registration, zero tracing inside the 60fps panel bodies, no subscriber install anywhere.
- Design-system discipline: zero hex/`Color32` literals (the one `Color32` is the documented palette-DATA swatch exception), zero emoji, all color via theme tokens and all symbols via phosphor `icons::*` (verified to exist), with chrome composed from the shared `crates/ui` codex widgets (`info_card`, `slot_editor_row`, `nav_tree_node`, `score_ring`, `palette_color_row`, `editable_list`, etc.) rather than bespoke frames.
- Error and panic hygiene is clean: no `unwrap`/`expect`/`panic!`/`todo!`/`dbg!`/`println!` in non-test code; Options are taken out with `let-else`, `if let`, `get_mut`, `map_or_else`, and `unwrap_or_*` fallbacks; test-only imports are `#[cfg(test)]`-gated to stay clean under `-D warnings`.
- Explicit per-file imports (not `use super::*`) with a comment explaining the `clippy::wildcard_imports` denial, and the "record the why" rule honored throughout (the `detail.clone()` rationale, the closure-vec borrow-conflict note, the pigeonhole bound on `next_free_slot_key`, the surface-discriminator buffer-collision note, the ActionId/Intent split, and the cast-precision-loss note).
- Pure helpers carry real unit tests: `coverage_complete` and `next_free_slot_key` are tested in `mod.rs`, including the interior-gap regression case.
