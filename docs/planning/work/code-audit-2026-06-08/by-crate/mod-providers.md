## mod-providers

This unit is high-quality, idiomatic Pixhaus code that tracks its rubric closely. The OpenRouter provider implements the verified openrouter-rs 0.10 image-output surface exactly, guards the untrusted PNG decode with an image 0.25 `Limits` cap, runs per-pixel work in `spawn_blocking`, and wins cancel ties with a biased `tokio::select!`. Error handling, secret hygiene, and the i18n key/data split all hold; the absence of `#[instrument]` is by design, since the span-per-request and `error!`-on-failure requirement is satisfied at the `job.rs` layer in services. The only confirmed gap is a thin direct-test hole on the OpenRouter `generate` cancel branch; everything else flagged was minor and most was rejected on review.

### Strengths

- `decode_png_data_url` is a textbook untrusted-decode guard per pixhaus-image: `ImageReader::with_format` + `Limits` (`max_image_width`/`height` = 8192) + `.decode()` rather than the bare `load_from_memory` free fn, with a `MAX_DECODE_DIM` constant whose comment records why (reject a decompression bomb, match the 8192 canvas ceiling, cite bible 24.3). Version-correct for image 0.25.
- The openrouter-rs 0.10 image surface is used exactly as the pixhaus-openrouter skill prescribes and as verified against the installed crate: `modalities([Image, Text])`, `image_config`, `Message::with_parts` + `ContentPart::text`/`image_url` for image-to-image, and reading the result by matching the `#[non_exhaustive]` `Choice::NonStreaming` and walking `c.message.images` via serde_json — never assuming a `.message` accessor, always treating `images == None` as a clean `BadOutput` rather than an unwrap.
- Cancellation is correct: `generate` wraps the request in a biased `tokio::select!` against `cancel.cancelled()` so a cancel wins ties, with a comment recording why; per-pixel decode/slice runs in `spawn_blocking` off the reactor, matching pixhaus-tokio and pixhaus-openrouter.
- Secret hygiene holds: the API key is transient, never logged, never stored in `GeneratedResult`/provenance; `register_openrouter` logs only `%error` from client build and is non-fatal (warn + fall back to mock), per modules/providers/CLAUDE.md and the openrouter skill.
- i18n boundary is respected: provider labels are stable keys (`provider.mock.label`, `provider.openrouter.label`) from `label_key()`; model names, prompts, and error text are carried as data, never baked into keys; `ProviderError` is split upstream into `message_key()` + `detail()` so no English literal reaches the UI.
- Error handling across the unit is clean: no `unwrap()`/`expect()`/`panic!`/`println!` in any non-test path; combinators are used correctly; `postprocess.rs` defines a proper thiserror enum with documented variants, `# Errors` sections, and slice bounds-safety reasoned in a comment.
- Tests are thorough for the pure helpers — determinism, prompt-sensitivity, `PixelBuffer` validity, base64-reject, over-limit-reject, encode/decode round-trip, chroma-key threshold edge, row-major slicing — with descriptive names; the synthetic `CompletionsResponse` is built by deserializing JSON (with a comment on the `#[non_exhaustive]` no-constructor constraint), and the live test is correctly `#[ignore]`d behind `OPENROUTER_API_KEY`.

### Checked and cleared (false positives)

- U29-1 (openrouter.rs:121-124, unfiltered upstream error string): rejected. The cited pixhaus-reqwest "strip the URL" rule is a secrets measure for keys carried in a query param; this module depends on openrouter-rs, not reqwest (so `without_url()` is not callable here), and the auditor itself concedes the OpenRouter key travels in the `Authorization` header, not the URL — no secret leaks when `job.rs` logs `error!(%error)`. The "NEVER log an API key" rule is satisfied; the rest is speculative defense-in-depth.
- U29-4 (mock.rs:62-78, no direct unit test for `MockProvider::generate`): rejected. The cited "every public function has at least one test" floor is already met — `tests/mock_generation_loop.rs` is a real `#[tokio::test]` that drives `generate` end-to-end through the `JobManager` on the Anchor path. The remaining ask (cover the `IdleAnimation` and post-sleep cancel branches directly) is a completeness preference against the ceiling, not a confirmable violation.
