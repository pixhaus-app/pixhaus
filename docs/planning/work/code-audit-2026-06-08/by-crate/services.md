## services

This group is high-quality, convention-aware service-layer code, and it earns that verdict honestly. Across the job system, undo/history, providers, the i18n service, the Codex subtree, and the demo fixtures, the load-bearing rules hold: spawning onto the ambient binary runtime never creating one, biased `select!` on a `CancellationToken`, no lock held across `.await`, `parking_lot::Mutex` on the one sanctioned shared store, thiserror enums with no panics outside tests, and a textbook keys-vs-data i18n boundary. The confirmed findings are all minor: one ownership/allocation deviation in the provider registry and a handful of O(n^2)/duplicate-resolution passes over bounded author-scale data, none of them correctness or policy breaks.

### Strengths

- Job system follows the runtime model exactly: detached tasks carry their own `tracing::info_span!` via `.instrument()`, the cancel path uses `tokio::select! { biased; ... }` so cancel wins ties, and results flow back to the UI lane over a channel.
- Error and panic policy is clean throughout: thiserror enums (`ServiceError`, `ProviderError`, `BuildError`, `ParseError`), `#[error(transparent)] #[from]` bridges to core, no anyhow, no `Box<dyn Error>`, saturating arithmetic instead of panicking math, and every `unwrap`/`expect` confined to `#[cfg(test)]`.
- The failure path never ships an English literal to the UI: messages carry a stable i18n key plus non-localized detail data, while the English thiserror Display is logged via `error!(%error)` — the split documented at every spot it shaped.
- tokio is pinned `default-features = false, features = ['rt','macros','time']` (not workspace `full`), with a comment explaining why the version is set directly — the exact lib-tokio minimalism the spine requires.
- The single sanctioned `Arc<Mutex<...>>` (the `ResultStore`) is documented as such, every critical section is a quick sync read/write with no `.await` crossing the guard, and `parking_lot::Mutex` is used per the lock-choice matrix.
- `Provider` avoids the async-trait crate: `generate` returns a hand-rolled `Pin<Box<dyn Future + Send + 'a>>` to keep `dyn Provider` object-safe, with the decision named in a comment.
- i18n boundary is clean and verified: `rust_i18n::*` appears only in `i18n.rs` and the single `i18n!` in `lib.rs`, the missing-key warning is `#[cold]`, off the hit path, on the `pixhaus::i18n` target, and tests are `#[serial]` with their own starting language per the skill's footgun.
- Codex keys-vs-data discipline is exemplary: validation, health, and coverage store stable `codex.*` keys confirmed present in `locales/codex.yaml`, while handles, names, and authors stay raw String data, never localized in this layer.
- Decisions are recorded where they live, per the repo rule: the builder-vs-blob fixture choice, the `EntryHealth` u16-thousandths-for-Eq choice, the explicit-imports-over-glob choice, and the separate-crate `#![allow(...)]` rationale in the integration tests.
- Tests are thorough and well-placed: integration tests in `tests/` exercise genuine public surface, bit_demo assertions interpolate the offending handle into descriptive failure messages, names read as behavior sentences, and error/None paths are covered.

- U12-1 (demo helpers lack direct tests): rejected — the named helpers are `pub(super)`, not `pub`, so the "every public function has at least one test" rule does not reach them, and their behavior is covered transitively by inline and integration tests; the testing skill explicitly discourages double-coverage of internal helpers.
- U12-2 (`ENTRY_COUNT`/`RELATIONSHIP_COUNT` doc/test gap): rejected — self-defeating; the consts are documented at mod.rs:524-528 and pinned against literals (`== 36`, `== 65`) at mod.rs:553-557, and the finding itself says "No change needed."
- U12-3 (`negatives_from` O(n^2) dedup is a style violation): rejected — the cited "iterators vs loops" rule endorses a for loop with side effects and names only throwaway `collect()` as the perf trap; no rule mandates a HashSet for a ~10-15-element fixture dedup, and the finding says "Leave as-is."
- U13-1 (history_round_trip asserts lack failure messages): rejected — the cited rule targets `is_ok()`/`is_err()` asserts specifically; this test has none, only bare `.unwrap()` (which already reports file:line + Debug) and two message-less boolean asserts the skill states no hard MUST for. A stylistic nicety, not a violation.
- U13-2 (history round-trip test proves multiple behaviors): rejected — the "one behavior per test" rule targets unrelated behaviors under a noncommittal name; here the sequential execute→verify→undo→verify steps are one round-trip narrative the name already states, and the finding concedes "No change required."
