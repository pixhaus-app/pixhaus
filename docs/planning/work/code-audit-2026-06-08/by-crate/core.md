## core

The core layer holds the line against the rubric. Across forty-plus files in four units - the domain model, the codex model, non-codex commands plus macros, and the two batches of codex commands - the load-bearing rules are met without exception: no egui/wgpu/IO/locks/unsafe in core's Cargo.toml or code, no localization (keys and ids only), no production unwrap/expect/panic (every one lives inside a `#[cfg(test)]` block under the crate-root test allow), typed `thiserror` errors with no anyhow or `Box<dyn Error>`, all mutation routed through faithfully undoable `Command` impls, and pixel data as a flat `Vec<u8>` with explicit stride. The findings that survived verification are minor - a no-op-rename undo/apply revision asymmetry and a couple of missing direct tests. Compliance is strong; this is the most disciplined group in the codebase.

### Strengths

- Boundary compliance is clean: core's `Cargo.toml` pulls only `serde` + `thiserror` (no egui/wgpu/io, not even glam/bytemuck until needed); no IO, network, locks, unsafe, or tracing anywhere in the layer.
- Error and panic policy is fully met: zero unwrap/expect/panic/todo/dbg/println outside `#[cfg(test)]`; every fallible path returns a typed `CommandError`/`PixelError`/`CompositeError`/`HandleError` via `thiserror` with correct `#[error(transparent)]` + `#[from]` use; no anyhow, no `Box<dyn Error>`.
- Pixel buffer is a textbook flat `Vec<u8>` with explicit stride and `checked_mul` overflow guards in both constructors; `pixel(x,y)` returns `Option<Rgba>` with an explicit bounds check, no unwrap at the call boundary.
- Copy/newtype discipline is exemplary: every id (SpriteId/LayerId/FrameId/ClipId/PixelBufferId/CodexEntryId/CodexFolderId/CoverageTemplateId) is a distinct Copy u64 newtype, with a `compile_fail` doctest proving a LayerId cannot pass where a SpriteId is expected; Copy is derived only on small heap-free types, never on String-bearing structs.
- All mutation routes through faithfully undoable `Command` impls: apply captures exactly what undo needs, undo restores it exactly (including list positions via `pos.min(len)` guards), and the no-reuse id invariant is re-established on the restore path with the why recorded at both spots.
- AI-result-as-command boundary is exactly right: `ApplyGeneratedAsset`/`ApplyGeneratedAnimation` take plain `(width, height, stride, Vec<u8>)`, never a services type; the `Option<Vec<u8>>` pending-vs-applied pattern reclaims pixels on undo and `estimated_size_bytes()` counts bytes only while the command holds them; `ApplyGeneratedAnimation` validates every frame before mutating, so a bad frame leaves the document untouched.
- i18n discipline is exact: `label_key()` returns stable `command.*` / `command.codex.*` keys, never display text; `CoverageLabel::Key` vs `Literal` keeps core from ever calling `tr()`; name/handle/prompt fields are doc'd as project content, not keys.
- The `swap_field_command!` macro carries a thorough doc comment, is genuinely reused at four-plus call sites, and is correctly scoped to the byte-identical single-field case (per commit b05edfb), with the extra-logic commands deliberately staying hand-written.
- The custom `CoverageKey` Serialize/Deserialize is the right call and is justified at the spot it shaped (a struct map key fails under JSON, so it serializes as `<entry>:<slot>` and splits on the first colon), with a round-trip test proving a colon-containing slot survives.
- Recording-the-why is followed precisely at the genuinely non-obvious decisions: the frames-first composite routing, the strict-LIFO-undo rationale, the option_option three-state guard with its scoped allow, the `struct_excessive_bools` lock-flags justification, and `dead_code` attributes pointing at the bible section that will retire them.
- Tests are strong and match the conventions: proptest for strided pixel readback, the full apply/composite/undo integration loop with a documented scoped test-only allow, dedicated tests for the trickiest invariants (template reuse undo, coverage non-bleed, position restoration), and the shared seed helper extracted into `test_support.rs` to kill ~28 copy-pasted seed fns.

### Checked and cleared (false positives)

- U1-2 claimed `composite_frame` has no test that calls it - rejected: it is directly tested at `commands/apply_generated_animation.rs:205-206` (happy path, asserting composited pixels) and `ui/tests/generate_loop.rs:134`; only the by-id FrameNotFound arm is genuinely untested, but the headline claim is wrong.
- U2-1 claimed the `CoverageKey` doc cites a nonexistent "save-format doc section 33" - rejected: the save-format doc does have section 33 ("Recommended V1 Format"), which lists JSON metadata as the V1 format; the citation resolves correctly and the proposed repoint to 7.5 would be less precise.
- U2-2 claimed `EntryVersion` is a public struct with no test - rejected: the cited rule covers public functions, and `EntryVersion` is a plain data struct with no public function; it is also constructed and asserted in `commands/codex/duplicate_entry.rs:140-153`.
- U2-3's sibling U2-3 (Codex::entry / Codex::relationships untested) - rejected: both are directly asserted in sibling command tests (`add_entry.rs:104`, `delete_entry.rs:77` for `entry`; `add_relationship.rs:90` reads a pushed Relationship back via `relationships()`), so the "not at all" claim is false.
- U3-3 claimed `label_key()` for the asset command is unasserted - rejected: `services/history.rs:202` and `:302` assert `"command.apply_generated_asset"` driven by a real `ApplyGeneratedAsset` instance, so a rename breaks those tests; the auditor missed the services-layer coverage.
- U4-2 claimed `add_entry_custom_slot::apply` violates "borrow in signatures; own only what you keep" by cloning the slot twice - rejected: that rule governs signature ownership, not redundant body clones; both clones have real ownership reasons (one is the undo snapshot the rule explicitly blesses), and CoverageSlot is small.
- U5-2 claimed `remove_relationship::apply` is the lone outlier bumping the revision before capturing undo state - rejected: `remove_anchor.rs:29-30` and `set_anchor.rs:56-57` also bump-then-capture, so the ordering is mixed across the unit and no rule mandates a specific order.
- U5-3 claimed `ReorderCoverageSlots` should model its `applied: bool` guard as an Option for type-state consistency - rejected: the finding self-describes as "no correctness defect" and "optional"; the bool is already a correct, working undo-before-apply guard, and the suggested Option::take is itself a runtime guard, so it does not better satisfy the cited type-state rule.
