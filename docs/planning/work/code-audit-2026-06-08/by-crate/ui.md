## ui

The `ui` group is in strong shape: across thirteen audited units the crate is among the cleanest in the codebase, with the load-bearing invariants holding firm. Theme tokens are the only color source, the deferred-intent seam is enforced by types rather than convention (read-only `ContribCtx` borrows, a single `&mut IntentSink`), the i18n boundary is structural (`MsgKey` makes displaying an unresolved key a compile error), and the 86-arm intent `match` is wildcard-free so a new variant fails the build until handled. Error, tracing, and design-system policies are satisfied with no real violations. The confirmed findings are all low or info severity: one latent panic dependent on a non-local invariant, two raw radius literals, a couple of i18n composition/coverage gaps, a handful of untested public helpers, and a serde round-trip asymmetry — polish, not structural debt.

### Strengths

- Theme-token discipline is total: every region frame, widget, and canvas chrome color comes from `theme.surface(...)`/`theme.roles.*`/`theme.accent.*` and the `SurfaceTier` elevation model, with zero hex/`Color32::from_rgb` literals in chrome code. The two real `Color32` uses (editing user palette RGBA, `Color32::TRANSPARENT` sentinel) are documented carve-outs, not token duplicates.
- The deferred-intent contract is enforced by the type system, not by discipline: `ContribCtx` exposes session/ui_state/theme as `&` and only `intents` as `&mut`, the lone in-frame `&mut String` scratch carve-out is documented at each spot, and every durable mutation routes through `history.execute`/`execute_returning` — not one arm writes the model directly.
- i18n boundary is exact: registries carry `MsgKey`, never display literals; `StatusLabel::Key{key,args}` splits localizable labels from verbatim `Data`; `JobMsg::Failed` stores the stable key plus non-localized detail so a language switch re-renders the error; user content (prompts, names, `Bit`) stays out of keys.
- Dyn is used only at genuine heterogeneous-collection boundaries (`Box<dyn Panel/Tool/Workspace>`) while the `Registry<K,V>` store stays monomorphic, and `mod.rs`'s const `_assert_boxable` guard fails the build the instant a registry trait regresses out of dyn-compatibility.
- Phosphor icons throughout via `crate::icons::*` with zero emoji, the no-tofu rationale recorded; brand assets expose `ImageSource` consts and every render site applies `TextureOptions::NEAREST`.
- Error/panic policy is clean across the group: no `unwrap`/`expect`/`panic!`/`println!` in non-test code; the sole `panic!`s sit in `#[cfg(test)]` arms chosen deliberately over `unwrap` to honor `disallowed_methods` even in tests.
- Tracing is correct for the layer: zero per-frame events on the 60fps paint path, with the single coarse `warn!` confined to the logic-phase job-failure drain, carrying structured fields and no secrets.
- The "record the why" rule is followed densely at the decision site — the egui panel-ordering contract, the playback-via-direct-mutation choice, the `Intent`-not-`Clone` `reemit` match, the onion-bake inline-composite gate with its 8K migration note, and the borrow-splitting scratch/draft carve-outs.
- Pure logic is correctly egui/i18n-free and well-tested: `playback.rs`, `view.rs` (with division/degenerate guards), `contrast.rs` (reference-anchored WCAG), and `layout.rs` carry edge-case table tests; egui 0.34 API usage (`global_style_mut`, `content_rect`, `consume_shortcut`, `from_rgba_unmultiplied`, `CornerRadius`) is version-correct throughout.
- Snapshot and end-to-end test design is sound: layout snapshots are reviewed `ResolvedLayout` dumps, and `generate_loop` drives the real prompt→job→result→command→composite→undo path through a live tokio runtime and the offline mock provider exactly as app boot wires it.

### Checked and cleared (false positives)

- U14-2 (`resolve.rs` per-frame Vec churn): rejected — the cited "no throwaway collect() in hot paths" rule does not apply; each `collect` produces a persistent `ResolvedLayout` field, and the author concedes "no change required in resolve.rs." The real per-frame concern lives in the out-of-unit region callers.
- U15-1 (`panel.rs` split `use` lines): rejected — the imports rule mandates only grouping (std/external/workspace/local), which panel.rs satisfies; single-line merging is nightly-only fmt behavior, not a prescribed convention. Cosmetic cross-file inconsistency, not a violation.
- U16-2 (`overlay.rs` untested paint fns): rejected as actionable — the functions are always-`None` no-op scaffolds with no asserted behavior yet; the test gap is a forward tracking note for when drawing bodies land, not a current defect.
- U17-2 (`wcag_contrast` re-exported, test-only consumers): rejected — the only concrete rule (every public fn tested) is satisfied with four unit tests and a doc; "a re-export needs a non-test consumer" is not a documented rule. A legitimate API choice.
- U18-2 (`codex.rs` painting widgets untested): rejected — the painting widgets are exercised by the `render_workspaces` egui_kittest harness, the verification path the ui-conventions skill prescribes for painting widgets; the pure helpers are unit-tested. The finding self-concludes "do not over-claim a violation."
- U20-3 (`Palette: Bit` HUD literal): rejected — `Bit` is canonical mock data (data, never a key segment) and the HUD is the named transitional carve-out; the finding asks only for a forward-looking comment, not a current rule fix.
- U21-3 (`results.len() as u64` bare casts): rejected — `usize as u64` is a widening no-op that fires no pedantic lint and passes the Stop gate; no rule requires annotating a clippy-clean cast for symmetry. The finding concedes "not a real defect."
- U22-1 (`SessionState` query helpers untested): rejected — all four (`is_generating`, `selected_is_anchor`, `selected_is_animation`, `result_frame_count`) are asserted in the sibling integration test `tests/generate_loop.rs`, a valid test location the auditor missed.
