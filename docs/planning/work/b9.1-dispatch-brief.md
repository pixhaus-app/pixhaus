# B9.1 — Core types + fixture rebuild

The first of five B9 sub-tasks. Lands the new Library / Entity / EntityKind data model, ts-rs exports, round-trip tests, and regenerated fixtures. Pre-launch breaking change — no migration path.

Read the design doc at `docs/planning/work/b9-project-library.md` (or its planning-workspace counterpart) before starting. The "Decisions locked" section at the top is canonical.

## What this task delivers

- New types in `core/src/project/library.rs`:
  - `Library { entities, groups, palettes, tags, ai }`
  - `Entity { id, kind, name, group_id, tags, defaults, content, ai, user_data, anchor_reference_id, created_at, updated_at }`
  - `EntityKind { Tileset, Tilemap, Reference, Custom(String) }` — exactly four variants
  - `EntityContent { Sprites { states }, Tileset { tileset }, Tilemap { scene }, Reference { sheet: ReferenceSheet } }`
  - `NamedSprite { id: StateId, state_name, sprite, engine_tags }`
  - `EntityDefaults { canvas_size, color_mode, default_palette_id, default_pivot, default_fps }` — all `Option<>`
  - `EntityGroup { id, name, parent_id, user_data }` — recursive grouping
  - `TagDefinition { id, name, color, auto_generated }`
  - `AiMetadata { suggested_tags, vlm_summary, embedding }`
  - `ProjectAi { style_corpus, project_lora_path, prompt_history }`
  - `TilemapScene { size, tilesets: Vec<TilesetReference>, layers: Vec<TilemapLayer>, properties }`
  - `TilesetReference { tileset_entity_id, first_gid }` — multi-tileset is in scope
  - `TilemapLayer { id, name, data, opacity, visible }`
  - `ReferenceImage` — opaque holder for the source bytes
  - **`ReferenceSheet { canonical, history, prompts, info }`** — structured sheet
  - **`SheetVariant { id, generated_at, image, composition, generation, extracted_palette }`**
  - **`SheetComposition { views, expressions, callouts, outfits, palette_swatch }`** — panel rectangles inside the sheet image
  - **`SheetPanel { region: Rect, label: String }`** — one rectangle within a sheet
  - **`GenerationProvenance { backend, model, prompt, seed, negative_prompt }`**
  - **`AssetInfo { fields: BTreeMap<String, String>, notes: Vec<String> }`**
  - **`PromptEntry`** and **`PromptResult`** types (define minimally; B10 fills in)
  - `ActiveTarget` enum that replaces `CanvasState::active_sprite`

- New ID newtypes in `core/src/project/id.rs`: `EntityId`, `StateId`, `GroupId`, `TagId`, `PaletteId`, `LoraId`, `LayerId`, **`SheetVariantId`** (if not present already). Use the existing `id_newtype!` macro pattern.

- Updated `Project` struct in `core/src/project/mod.rs`:
  - Replace `pub sprites: Vec<Sprite>` with `pub library: Library`
  - Replace any `CanvasState::active_sprite` usage with `pub active: ActiveTarget`
  - Bump `SchemaVersion` major. Document the bump in the rustdoc.

- ts-rs export for every new type. The TS mirror lands in `ui/src/lib/types/` per the existing convention.

- Round-trip tests in `core/tests/library_round_trip.rs`:
  - Empty Library serialises and deserialises to the same value
  - A Library with one of each `EntityKind` variant round-trips
  - Custom entity with five states round-trips, state order preserved
  - Custom entity with an `anchor_reference_id` set round-trips (ID preserved, no resolution required)
  - Reference entity with a minimal `ReferenceSheet` (single canonical variant, empty composition / history / prompts) round-trips
  - Reference entity with a populated `SheetComposition` (one of each panel kind plus a palette swatch) round-trips, `Rect` values preserved
  - TilemapScene with three tilesets round-trips, `first_gid` values preserved
  - Round-trip uses `rmp-serde` (matches the project file format)

- Fixture rebuild script at `scripts/rebuild-fixtures.sh` and `.ps1`:
  - Walks `examples/`, finds every `.pixhaus` fixture
  - Loads each under the OLD schema (use a temporary deserialise path or a checked-in copy of the old types)
  - Translates: each `Sprite` becomes a `Custom("Sprite")` entity with one state; per-sprite tilesets get hoisted to project-level `Tileset` entities, deduplicated by content hash
  - Saves under the new schema, replaces the old file
  - Self-deletes after running successfully (the script is one-shot — committing the script's source is fine, but a final `git rm scripts/rebuild-fixtures.{sh,ps1}` in the same PR removes it from main)

- Pre-B9 file rejection: the schema-version reader returns a typed error `SchemaError::PreReleaseFile` with the message "This file was created with a pre-release Pixhaus and is not supported. Re-create it with the current version." No migration path.

## Notes for the implementer

- The existing `Sprite.tilesets: Vec<Tileset>` becomes a problem: under the new model, tilesets are project-level entities, not sprite-scoped. The cleanest path is to delete `Sprite.tilesets` and have Tilemap layers reference Tileset entities by id. But Sprite is also used as the content of `NamedSprite` inside Custom-kind entities, where it might still want local tilesets for sprite-internal tilemap layers. **Decision deferred: ask in PR review.** A safe interim: keep `Sprite.tilesets` for now, mark it deprecated in the rustdoc, and route new code to project-level tilesets. The real cleanup is a follow-up PR.
- The `prompt_history` field type is intentionally vague (`Vec<PromptHistoryEntry>`). Define `PromptHistoryEntry` minimally — `{ verb_name: String, prompt: String, timestamp: i64 }` — and let the verb runtime own the richer shape.
- Use `serde(skip_serializing_if = ...)` aggressively. An entity with no tags should not emit an empty `tags: []` field. Match the pattern already in `UserData::is_empty`.
- The `EntityKind::Custom(String)` discriminant in `#[serde(tag = "kind", content = "value")]` form serialises as `{ "kind": "Custom", "value": "Character" }`. Verify this is what ts-rs emits cleanly on the TS side; if it produces an awkward type, switch to `serde(untagged)` or adjust.
