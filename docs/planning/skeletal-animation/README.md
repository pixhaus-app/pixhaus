# 2D Skeletal Animation Tools

This category covers industry-standard bone-based rigging and animation tools that have become foundational for modern 2D game character animation. These tools enable artists to create movement using deformable skeletons, inverse kinematics, mesh deformation, and timeline-driven animation rather than frame-by-frame drawing.

## What goes here

This cluster documents tools designed specifically for skeletal (bone-based) 2D animation, including:

- Editor and timeline interfaces for building bone hierarchies
- Rigging workflows (attaching artwork to bones, weight painting)
- Inverse kinematics (IK) and constraint systems
- Mesh deformation techniques (linear, bezier, or mesh-based)
- Runtime libraries for game engine integration
- Export formats and animation data structures

## Why this matters for SpriteMaster

Skeletal animation tools occupy a unique space between frame-by-frame hand animation (traditional) and 3D skeletal systems. They are the dominant approach for:

- Mobile game character animation (DragonBones, Spine)
- VTuber and gacha character rigging (Live2D)
- Indie and mid-budget 2D games (Spine, Spriter)
- Interactive web experiences (Rive)
- Physics-driven supplemental motion (Creature)

Understanding these tools' approaches to rigging, export, and runtime integration is essential for designing animation tooling that competes or integrates with existing workflows.

## Tools covered

1. **Spine (Esoteric Software)** — Industry standard; mature, well-documented, widely adopted
2. **Live2D Cubism** — 2.5D mesh deformation; dominant in VTuber and gacha sectors
3. **DragonBones** — Free, open-source; strong in Asian mobile game markets
4. **Rive** — Modern; state machine-driven interactive animation for web
5. **Spriter Pro** — Early skeletal tool; still used in indie development
6. **Creature (Kestrel Moon)** — Physics and curve-driven procedural animation
7. **AnimeEffects** — Open-source mesh deformation for frame-based animation

## Key differentiators

- **Runtime story**: How animations are exported and integrated into game engines (critical for usability)
- **Deformation model**: Linear/FFD/mesh-based approaches affect animation quality and file size
- **IK/constraints**: Sophistication of inverse kinematics and binding systems
- **Export formats**: Proprietary vs. standard; runtime library support across engines
- **Pricing model**: One-time license vs. subscription; commercial tiers and restrictions
