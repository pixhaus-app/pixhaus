# LDtk (Level Designer Toolkit)

## Quick facts
- Vendor / maintainer: Deepnight Games (open-source)
- License / pricing model: MIT (free)
- Price point (current): Free
- Platforms: Windows, macOS, Linux
- First released: 2020
- Last meaningful update: 2024 (0.5+)
- Source available: Yes (GitHub, full source code)
- Primary use case: Modern JSON-first tilemap and level editor with autolayering and entity placement

## Origin and purpose

LDtk was created by the director of Dead Cells to address pain points in tilemap editors: cumbersome autotiling, opaque rule systems, and limited entity placement. The design philosophy is JSON-first: the editor generates clean, well-documented JSON that developers parse easily.

LDtk emphasizes speed, visual clarity, and developer experience. It's younger than Tiled (first released 2020) but has gained rapid adoption in the indie community.

## Tile editing capabilities

LDtk provides visual tile placement with modern QOL features:

- **Stamp brush** — Place tiles individually or as pre-drawn patterns.
- **Fill tools** — Fill regions or lines.
- **Eraser** — Remove tiles.
- **Random placement** — Assign probability weights to tiles for variation.
- **Rectangle and line select** — Select areas for bulk operations.

The UI is clean and modern, with clear visual feedback.

Tiles are selected from a Tileset panel. Unlike Tiled, LDtk focuses on simplicity: less configuration, more automation.

## Autotile / wang tile / rule tiles

LDtk's autotiling is called "Autolayers" — a powerful feature designed to reduce manual tile work:

**Autolayer rules** — Define rules that automatically generate tiles based on conditions:

- "If this manual tile layer has a tile here, place this autotile layer tile there."
- "If there's water above and grass below, place this transition tile."
- Visual rule editor with examples; no code required.

**Pattern matching** — Rules can check 3x3 neighborhoods around each tile, enabling complex transitions (corners, edges, internal patterns).

**Crush/biome system** — Group related autotiles (grass, dirt, stone) into a "biome" that auto-detects and swaps.

**Layer grouping** — Organize autolayers into folders; rule order is customizable.

This approach is less "autotile system" and more "content generation pipeline." It's powerful and flexible, though requires more setup than Tiled's simpler terrain system.

## Multi-layer maps

LDtk supports several layer types:

**Tile Layers** — Standard tilemap grids.

**Integer Grid Layers** — Grid-based metadata (not visual tiles) for collision, danger zones, etc. Visual representation is optional.

**Entity Layers** — Free-form entity placement with custom properties.

**Auto Layers** — Generated by rules (see autotiles above).

Layers have visibility toggles and can be hidden/locked. Nesting and grouping are supported.

Layers are visual and intuitive; LDtk's UI makes layer management straightforward.

## Tile atlas integration

**Tileset definition** — A Tileset is embedded or external:

- Specify the sprite sheet image and tile size.
- LDtk auto-detects tile boundaries (with manual offset if needed).
- Define custom properties per tile (not commonly used; most metadata goes in entities).

**Tilesets are simple** — No terrain type assignment or complex metadata. LDtk pushes complexity to autolayer rules instead.

This simplicity is intentional: LDtk separates concerns (tileset = visual, autolayers = logic).

## Export and import

**Export formats** — LDtk exports JSON natively:

- Well-documented JSON schema (published and version-controlled).
- Includes tileset data, layers, entities, and autolayer definitions.
- JSON is text-based, easy to parse in any language.

**Optional Tiled export** — LDtk can also export to Tiled's TMX format for compatibility, though JSON is the recommended format.

**Import** — LDtk reads its own .ldtk project files. It does not import from other editors (no Tiled import).

**Game engine integration** — Community libraries and importers exist for:

- **Godot** — Community importers available.
- **Unreal** — Community plugins.
- **GameMaker Studio 2** — Community importers.
- **Custom engines** — JSON is easy to parse; many teams write their own importer.

LDtk's philosophy is developer-friendly: clear JSON output means minimal friction during engine integration.

## Scripting and extensibility

LDtk does not have a scripting system like Tiled's Lua. Instead:

- Autolayer rules are visual; no scripting required.
- Custom logic is implemented in game code by parsing the JSON.
- The JSON is designed to make this straightforward.

Extensibility is through JSON customization: developers add custom properties to entities and parse them in code.

No UI extensions or plugin system is available.

## How it fits the asset pipeline

Typical workflow:

1. Artist creates tileset sprite sheet (grid of tiles).
2. Artist exports as PNG.
3. Level designer imports tileset into LDtk.
4. Level designer creates tile layers and entity layers.
5. Level designer sets up autolayer rules (if needed).
6. Level designer exports as JSON.
7. Game developer parses JSON and integrates into the engine.

LDtk is positioned late in the pipeline, similar to Tiled, but with more emphasis on entity placement and metadata than tile painting.

## Workflow strengths

- **Modern design** — Clean, intuitive UI with excellent UX.
- **JSON output** — Well-documented, easy to parse; minimal friction during integration.
- **Autolayers are powerful** — Visual rule editor enables complex tile generation without code.
- **Entity-first design** — Strong support for placing and configuring game objects (NPCs, spawn points, triggers).
- **Visual backup system** — Automatic crash recovery and snapshots.
- **Free and open-source** — MIT license; no licensing concerns.
- **Active development** — Deepnight Games (the creators) actively maintain and improve it.

## Workflow gaps

- **No Tiled import** — If your team already has Tiled maps, you cannot easily convert them.
- **Smaller ecosystem** — Fewer community importers and plugins than Tiled (though growing).
- **No collaborative editing** — Single-user only.
- **Entity layer is lightweight** — Good for placing objects, but not a full entity editor (no visual scripting or property inheritance).
- **Limited to orthogonal grid** — No isometric or hexagonal grid support (as of 2024).

## Version history

LDtk reached 1.0 in 2021 and has been actively developed since. Version 0.5+ (2024) includes refinements to autolayers and entity placement.

## Interaction with related tools

- **Deepnight Games tools** — LDtk is part of a toolset; some indie developers use it alongside other Deepnight tools.

- **Community importers** — Growing ecosystem of engine-specific importers.

## Comparison with Tiled

| Feature | Tiled | LDtk |
|---------|-------|------|
| Maturity | Established (since 2008) | Newer (since 2020) |
| Autotiling | Terrain + Wang tiles | Autolayers (visual rules) |
| Grid support | Orthogonal, isometric, hexagonal | Orthogonal only |
| Export formats | TMX, JSON, Lua, CSV | JSON, TMX (optional) |
| UI | Traditional | Modern, minimalist |
| Scripting | Lua support | No scripting; visual rules |
| Community size | Large | Growing |
| Best for | Established pipelines, multi-format needs | Modern workflows, JSON-first |
